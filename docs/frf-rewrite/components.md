# 富士搖滾攻略：Notion 元件寫法與寫作規則

這份給 Gina 和幫忙改稿的 AI 用。照這裡的寫法在 Notion 寫，同步到網站後會自動變成對應的版面。
網站端的程式在 `src/lib/rehype-frf-components.mjs`、`src/lib/rehype-frf-who.mjs`、`src/lib/frf-links.mjs`，
示範內容在 `scripts/fixtures/frf-components-demo.md`，截圖在 `screenshots/layout/`。

## 先講原則：三種元件都用 Notion 的「表格」寫

同步腳本會把 Notion 表格原樣轉成網站的表格，粗體、連結都會留著。
提示框（callout）和切換清單（toggle）裡面的東西，同步時會被拆成一般段落，所以不適合放有欄位的內容。

做法：

1. 在 Notion 輸入 `/表格`（或 `/table`）新增一個簡單表格。
2. **第一列第一格**寫記號：emoji 加上固定的兩到三個字。記號後面可以接標題。
3. 第一列其他格是欄位名稱，網站會拿來當小標籤。
4. 從第二列開始寫內容，一列一項。

| 元件 | 第一格的記號 | 例子 |
| --- | --- | --- |
| 預算總覽卡 | `💰 預算總覽` | 💰 預算總覽：露營最省玩法 |
| 決策卡 | `🧭 如果你` | 🧭 如果你：最後一晚想怎麼走？ |
| 時間軸 | `🕒 時間軸` | 🕒 時間軸：抵達日從成田到苗場 |

emoji 和字都要有，只寫 emoji 或只寫字都會被當成一般表格。記號和標題中間用全形冒號「：」。
Notion「標題列」開不開都可以。

## 💰 預算總覽卡

放在預算類文章的開頭附近，讓讀者第一眼就看到「總共要多少、包含什麼、沒算什麼」。

**欄位**：第一欄是項目，第二欄是金額，第三欄是補充說明（可以空著）。

**特別的項目名稱**（寫在第一欄）：

| 第一欄寫 | 網站上會變成 |
| --- | --- |
| 總計（或「合計」） | 卡片最上面的大數字，第三欄變成大數字下面的一行說明。「總計」兩個字不會印出來 |
| 小計：固定開銷 | 粗線分隔的小計列，顯示成「固定開銷小計」 |
| 還沒算進去（或「未含」「不含」） | 卡片下方的紅色提醒，寫沒算進總額的東西 |
| 來源 | 卡片最下方的小字，放官網連結和年份 |
| 其他任何名稱 | 一般明細列 |

「總計」那列放在表格哪裡都可以，網站會把它移到最上面。

**Notion 裡這樣寫：**

| 💰 預算總覽：露營最省玩法 | 金額 | 說明 |
| --- | --- | --- |
| 總計 | 約 ¥96,000～104,000 | 日本當地開銷，含四天飲食，不含機票與雜支（2026） |
| 三日券 | ¥62,700 | 先行價 ¥57,000＋海外購票手續費 10% |
| 露營券 | ¥6,000 | 全期間計一次 |
| 新幹線 | ¥13,200 | 上野⇄越後湯澤，自由座來回 |
| 接駁巴士 | ¥2,000 | 越後湯澤⇄苗場，來回各一次 |
| 小計：固定開銷 | 約 ¥84,000 | |
| 四天飲食 | ¥12,000～20,000 | 週四到週日，不含酒水 |
| 還沒算進去 | 機票（廉航約 NT$8,000～12,000，傳統航空約 NT$15,000～18,000），以及網卡、保險、基本裝備 | |
| 來源 | 官網票價頁（2026），每年略有不同，出發那年請以官網為準 | |

**寫作提醒**

- 每個金額都要帶年份。年份寫在「總計」的說明或「來源」列一次就好，不用每列重複。
- 總額和導言、速覽、懶人重點講的數字要一樣。只差在含不含某一項時，用「小計」把兩個數字都放進卡片，讓讀者看得出差在哪。
- 「來源」那格的官網名稱要做成 Notion 連結。

## 🧭 決策卡

讀者要「選一個」的地方用這個：住哪裡、怎麼回程、要不要買某樣東西。
取代「好處／要有心理準備／怎麼訂」這種一層包一層的條列。

**固定四欄**，表頭一定是這四個（Gina 定案，2026-10-18）：

| 欄位 | 寫什麼 | 網站上顯示成 |
| --- | --- | --- |
| 🧭 如果你 | 讀者的情況，例如「當天一定要回東京」 | 卡片上方的小字「如果你：……」（不用自己寫「如果你」） |
| 怎麼做 | 一句話的做法 | 卡片標題，放大加粗 |
| 代價 | 要多花的錢、時間，或會錯過什麼 | 卡片裡的「代價」 |
| 來源 | 官方連結＋年份，例如「岩盤 OPTIONAL SERVICES（2026）」 | 卡片裡的「來源」 |

- 第一格的記號後面可以接一個問題，例如「🧭 如果你：最後一晚想怎麼走？」，問題會印在卡片上方。
- **空格那一項在這張卡上不顯示**。例如沒有官方來源，「來源」空著就好。
- **紅色卡片**：「如果你」那格開頭加 `⚠️`，這張卡會變成紅色邊框。只用在「不照做會多花錢、會趕不上車」的選項。
- 欄位照表頭名稱對應，四欄的順序寫錯也認得，但請照上面的順序寫，比較好檢查。
- 標準就是這四欄。如果多加了其他名稱的欄位（例如「路線」），網站還是會顯示（排在代價和來源中間），但請盡量把內容併進「怎麼做」或「代價」。

**Notion 裡這樣寫：**

| 🧭 如果你：最後一晚想怎麼走？ | 怎麼做 | 代價 | 來源 |
| --- | --- | --- | --- |
| ⚠️ 當天一定要回東京 | 比壓軸提早 1.5～2 小時離場下山 | 壓軸看不到；下山接駁巴士約 40 分鐘，散場前後排隊可能超過 1 小時（2026） | |
| 一定要看完壓軸，有訂到房 | 當晚住苗場或越後湯澤，隔天再走 | 多住一晚；週一接駁巴士 5:00～12:00，熱門時段排隊約 1～2 小時，新幹線時間要抓寬一點（2026） | |
| 要看完壓軸，又沒有住宿 | 搭岩盤新宿直達夜行巴士 | ¥14,000；凌晨 1:00 從會場巴士中心發車，清晨 6:00 到新宿，要跟門票一起買或之後加購 | 岩盤 OPTIONAL SERVICES（2026） |

「來源」那格的名稱要做成 Notion 連結。

**寫作提醒**

- 一張決策卡兩到四個選項。超過四個，先想想是不是兩個問題混在一起。
- 「怎麼做」一句話就好，細節放「代價」。
- 每個選項都寫「代價」，讀者才知道取捨在哪。
- 代價裡的金額、時刻一樣附年份。

## 🕒 時間軸

一步一步走的流程用這個：抵達日從機場到會場、回程那天、換手環的流程。
取代「第一段、第二段」底下塞了很多層條列的寫法。

**欄位**：

- 第一欄：站名或步驟名，網站會畫成綠色膠囊，跟現在的路線圖同一套樣式。
- 第二欄：在這一站要做什麼（怎麼走）。
- 第三欄以後：自己取欄位名稱，例如「時間」「費用」，網站會變成小標籤。
- 欄位名稱是「注意」「提醒」「備註」的，會變成一行小字說明；開頭加 `⚠️` 會變紅色。
- 最後一站（終點）可以只寫站名和注意，其他格空著。

**Notion 裡這樣寫：**

| 🕒 時間軸：抵達日從成田到苗場 | 怎麼走 | 時間 | 費用 | 注意 |
| --- | --- | --- | --- | --- |
| 成田機場 | 搭 Skyliner 直達上野 | 41 分鐘 | ¥2,580 | 線上買票掃護照，可以刷臉進站 |
| 上野站 | 換上越新幹線到越後湯澤 | 約 80 分鐘 | 自由座來回約 ¥13,200 | 去程建議先在網路上劃指定席 |
| 越後湯澤站東口 | 搭接駁巴士上山 | 約 40 分鐘 | ¥2,000 含來回 | ⚠️ 前夜祭當天（週四）12:00 才開始發車 |
| 苗場會場 | | | | 在王子飯店前的乘車場下車，回程也在這裡搭 |

**跟現在的路線圖差在哪**：原本「> 機場（45min）→ 上野車站（80min）→ 越後湯澤車站（40min）→ 苗場會場」這種寫法照樣可以用，
適合放在段落開頭當一行總覽。時間軸是詳細版，每一站多了做什麼、時間、費用、注意。
同一篇兩個都放的話，路線圖放開頭，時間軸放在交通段落裡，數字要一致。

**寫作提醒**

- 一站一列，不要把兩個轉乘塞在同一列。
- 其他選擇（計程車、路線巴士）不要塞進時間軸，另外用一段文字或決策卡寫。

## 一般表格：四欄以上，手機自動改成卡片

不用加記號。四欄以上、內容 12 列以內的表格，在手機上（寬度 640px 以下）會變成一列一張卡片：
第一欄是卡片標題，其他欄是「欄位名稱：內容」。電腦上還是一般表格。

- 第一欄請放「這一列是什麼」（住宿名稱、營區名稱、品項），卡片標題才看得懂。
- 欄位名稱要短（四個字以內最好），手機上的標籤欄寬度有限。
- 三欄以下的表格（例如預算表）在手機上本來就放得下，不會改。

**不轉卡片的文章**：`naeba-food`（苗場美食）的表格在手機上維持原本的表格，不轉卡片，之後會換別的呈現方式。
名單寫在程式裡（`src/lib/rehype-frf-components.mjs` 的 `NO_STACK_SLUGS`），Notion 不用做任何事。
要加其他文章請跟網站端說，把 slug 加進名單。名單裡的文章，有記號的元件表格（💰、🧭、🕒）照樣會轉。

截圖：`screenshots/layout/14-stack-table-hotels-after-mobile.png`

## 文章開頭：本篇適合、閱讀時間（Notion 寫法不變）

原本的寫法照舊：

> 👤 **本篇適合：** 🔰 新手首衝（預算有限、想用最低成本去一次音樂祭的人）
>
> **⏱ 閱讀時間：** 約 6 分鐘

網站會把它從內文拿出來，變成標題下方的小標籤：

- 「🔰 新手首衝」「👑 老手升級」「🌐 通用必修」這種開頭有 emoji 的短詞，變成標籤。
- 括號裡的說明，變成標籤下面一行小字「本篇適合：……」。
- 閱讀時間變成一個標籤。沒寫的話網站自己算。
- 「本篇適合：」後面空著，網站什麼都不顯示。但還是請補上，讀者靠它判斷要不要讀。

身分標籤用「／」「｜」「＋」分開都可以。

## 站內連結（Notion 寫法不變，網站自動處理）

連到其他攻略文章的連結，網站一律顯示那篇文章**現在的標題**，連結文字寫什麼都會被換掉，也不會出現「#02」這種編號。
連到文章裡某一段（網址有 `#`）的連結，網站只拿掉編號，保留原本的文字。外部網站、主題頁的連結不動。

所以 Notion 裡的連結文字可以隨手寫，但句子要讀得通。例如「詳見 [新手預算] 」換成完整標題後，前後文還是要順。

## 寫作規則

### 一個區塊只做一件事

| 區塊 | 只放 | 不要放 |
| --- | --- | --- |
| 導言（meta） | 一句話講完這篇的結論 | 細節數字列表 |
| 速覽 | 每年會變的數字，每項附年份 | 建議、心得 |
| 預算總覽卡、決策卡、時間軸 | 讀者要比較、要照著走的內容 | 故事、心得 |
| 內文段落 | 為什麼、怎麼判斷、實際經驗 | 再抄一次速覽的數字 |
| 懶人重點 | 讀完要「做」的事，三到四點 | 重講速覽的數字 |
| 結語 | 一兩句收尾 | 第三次整理重點 |

同一件事（例如「提早 1.5～2 小時下山」）在一篇裡最多出現兩次：一次在內文說明，一次在懶人重點。

### 提示框

- **每一個小段落（H3）最多一個提示框。** 想放第二個，先問自己是不是其實是內文。
- **紅色警告（⚠️、🚫、❗）只用在兩種情況：會多花錢、會趕不上車。** 其他的注意事項用 💡（綠色）或直接寫在內文。
- 提示框第一句加粗，一句話講完重點，後面最多兩三句說明。

### 條列

- 條列最多兩層。第三層一律改寫成段落或表格。
- 三個以上「**標籤：** 內容」格式、而且每項欄位一樣的條列，改成表格或決策卡。
- 選擇題（住哪、怎麼回、買哪個）用決策卡；照順序走的流程用時間軸。

### 數字與來源

- 價格、日期、班次一律附年份，例如「¥2,000（2026）」。
- 官方數字附來源連結（官網票價頁、岩盤 OPTIONAL SERVICES）。
- 同一個數字在不同文章要寫得一樣，名稱也一樣（例如三日券是「先行」還是「早鳥」，全站選一個）。

### 用字

- 繁體中文、台灣用語，全形標點（，。：；「」（））。
- 不用破折號（兩個長橫線連在一起的那種），改用逗號、冒號或拆成兩句。
- 不顯示文章編號，新手篇和老手篇是平行的兩欄，用「新手篇」「老手篇」稱呼。
- 不推銷行程，只寫實際走過、查得到來源的資訊。

## 新手篇／老手篇切換（自動）

Notion 標題同一個編號（例如都是「# 02」），一篇客群標籤是新手、一篇是老手，網站會在標題下方自動放「🔰 新手篇｜👑 老手篇」切換。
目前三組：02 新手預算／老手預算、04 露營／住宿進階、05 裝備入門／裝備進階。新增一組只要編號相同、客群標籤一新一老。
